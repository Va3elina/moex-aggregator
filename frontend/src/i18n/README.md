# i18n — правила для переводчиков (людей и агентов)

Цель: английская версия интерфейса для демо. Русский — источник истины и дефолт.

## Механика

- **Русский текст = ключ.** `t('Открытые позиции')` → en/*.json содержит `"Открытые позиции": "Open interest"`. Нет перевода → вернётся русский.
- В React-компонентах: `const { t } = useTranslation()` из `react-i18next`.
- Вне React (чарты, утилиты, константы модуля): `import { t } from '../i18n'` (путь относительный). **Не вызывать `t()` на верхнем уровне модуля** — константа вычислится один раз на русском. Оборачивать в функцию или вызывать в рендере.
- Даты: вместо `'ru-RU'` в `toLocaleDateString`/`Intl.*` → `dateLocale()` из `../i18n`. Массивы месяцев → `monthShort(i)` / `monthGenitive(i)` (0-based).
- Числа: `formatNumber` не трогать — формат «1 234.56» одинаков для обоих языков.
- Подстановки: `t('Осталось {{n}} дней', { n })`, в json: `"Осталось {{n}} дней": "{{n}} days left"`.
- Строки с переменными в шаблонной строке (`` `${x} бумаг` ``) → перевести в подстановку `t('{{x}} бумаг', { x })`.
- JSX с разметкой внутри фразы (`<b>`, ссылки) → разбить на куски и перевести каждый, либо `<Trans>` из react-i18next. Простой вариант предпочтителен.

## Словари

- Один файл на домен: `src/i18n/en/<domain>.json` (`nav.json`, `oi.json`, `landing.json`, ...). Плоский объект `{ "рус": "eng" }`.
- Дубликат ключа в двух файлах с **одинаковым** переводом — ок. С разным — warning в dev-консоли; оставить только один.
- Общие короткие слова («Закрыть», «Загрузка…», «Физлица») уже в `nav.json` — не дублировать.
- Ключ — точная строка из кода, включая «ё», типографские кавычки «», тире —, многоточие … . Проверяй, что ключ в json совпадает с аргументом `t()` посимвольно.

## Что переводить

- Всё, что видит пользователь: заголовки, кнопки, легенды, тултипы, подписи осей, тексты ошибок, плейсхолдеры, `aria-label`/`title`, тексты методологии.
- `useHead` title/description страницы — да (`t()` внутри объекта в рендере).

## Что НЕ трогать

- Комментарии в коде — оставлять русскими.
- Названия компаний/фондов/УК из API — не переводить (данные из БД).
- Ключи аналитики (`track('theme_toggle')`), пути, id, CSS.
- Юридические страницы (`pages/legal`, Privacy/Refund/Offer) — не переводить.
- Файлы вне своего домена (см. распределение в задании) — чтобы не конфликтовать с параллельными правками.

## Стиль перевода

- Финансовый английский, как в терминале Bloomberg/TradingView: *Open interest, Retail/Institutions, Net position, Free float, Fund flows, Market breadth, NAV, Rebalance*.
- Кратко: русская фраза часто длиннее — не раздувать. Кнопки — 1–2 слова.
- Названия индикаторов: Market map, Open interest, Fund flows, Fund trades, Market breadth, Seasonality, Capital flows, Buffett indicator. Использовать их последовательно.
- «Физлица/Юрлица» → Retail / Institutions. «Бумага» → security (или stock, если точно акция). «ОИ» → OI. «БПИФ» → ETF. «УК» → asset manager. «СЧА» → NAV. «Ребаланс» → rebalance.

## Проверка

```bash
cd frontend && npx tsc -b && npx eslint <изменённые файлы>
```
Затем прогнать `scripts/i18n-check.mjs` (ищет ключи `t('…')` без перевода в своём домене).
