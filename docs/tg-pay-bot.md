# Бот оплаты Фрейма в Telegram — ТЗ

Статус: к реализации. Дата: 2026-11-17.

## Зачем

Большая часть покупателей приходит из Telegram-канала, а на сайте
регистрируется через VK ID или Яндекс ID. Почтой из этих аккаунтов никто не
пользуется, поэтому если человек не дошёл до оплаты, связи с ним больше нет.

Бот нужен не для того, чтобы принимать платежи, а чтобы **сохранить контакт**:
кто нажал /start, тому бот может написать. Это и напоминание о брошенной
оплате, и предложение скидки, и сообщение «не прошло продление».

## Рамки (что решено)

1. **Отдельный бот**, не @framesignalbot. Сигналы приходят много раз за день,
   такой бот обычно в беззвуке, и сервисные сообщения там утонут. Ещё один риск:
   пользователь блокирует бот сигналов и вместе с ним теряет канал оплаты, и
   наоборот.
2. **Платёж принимает сайт, а не Telegram.** Цифровые подписки внутри
   Telegram продаются только за Stars, вывести их на счёт ИП нельзя. Бот ведёт
   на `/pricing`, где уже есть развилка «карта / привязка счёта СБП».
   **Никогда не давать прямую ссылку на форму T-Bank.** Иначе СБП пройдёт без
   привязки счёта, и автопродления не будет.
3. **Вход только способами, разрешёнными законом.** 406-ФЗ (поправки в 149-ФЗ,
   действуют с 01.12.2023) запрещает российскому сайту авторизовать пользователя
   через Telegram. Значит:
   - нельзя логинить по `telegram_id`, по `initData` Mini App или по
     одноразовой ссылке, присланной в бот;
   - можно привязать чат бота к аккаунту, **после того** как человек вошёл на
     сайт через VK, Яндекс или почту. Так уже устроена привязка @framesignalbot
     (миграция `007_telegram_link.sql`).
4. **Обычная URL-кнопка, без Mini App.** Mini App ценен как раз авторизацией по
   initData, а её использовать нельзя. Без неё Mini App ничего не добавляет.

## Пользовательский путь

```
пост в канале ── t.me/<bot>?start=<кампания>
        │
        ▼
бот: приветствие, что даёт Фрейм
     [Выбрать тариф] → framedata.ru/pricing?src=tg_bot&tgc=<claim-токен>
     [Присылать скидки и напоминания] (согласие на рекламу, по желанию)
        │
        ▼
сайт: вход VK / Яндекс / почта (как сейчас)
      фронт видит tgc → POST /api/tg-pay/claim → чат привязан к user_id
        │
        ▼
/pricing: развилка карта / СБП-привязка (без изменений)
        │
        ▼
подписка active → бот: «Доступ открыт, тариф X до DD.MM»
```

Если человек не дошёл до конца, у нас остаётся `chat_id`, и по нему работают
дожимы (см. ниже).

## Компоненты

### 1. Миграция `db/migrations/116_tg_pay_bot.sql`

```sql
-- Лиды бота оплаты: один Telegram-пользователь = одна строка.
-- chat_id приватного чата = Telegram user id, но писать можно только тем,
-- кто нажал /start именно в этом боте.
CREATE TABLE IF NOT EXISTS tg_pay_leads (
  chat_id            BIGINT PRIMARY KEY,
  username           VARCHAR(64),
  first_name         VARCHAR(128),
  start_param        VARCHAR(64),          -- кампания первого входа
  first_seen_at      TIMESTAMPTZ NOT NULL DEFAULT now(),
  last_seen_at       TIMESTAMPTZ NOT NULL DEFAULT now(),
  user_id            INTEGER REFERENCES users(id) ON DELETE SET NULL,
  linked_at          TIMESTAMPTZ,
  consent_marketing  BOOLEAN NOT NULL DEFAULT false,  -- 38-ФЗ ст. 18
  consent_at         TIMESTAMPTZ,
  opted_out_at       TIMESTAMPTZ,          -- /stop
  blocked_at         TIMESTAMPTZ           -- Telegram ответил 403
);
CREATE INDEX IF NOT EXISTS idx_tg_pay_leads_user ON tg_pay_leads(user_id);

-- Одноразовые claim-токены: бот → сайт. Живут 24 ч (человек может войти не сразу).
CREATE TABLE IF NOT EXISTS tg_pay_claims (
  token      VARCHAR(64) PRIMARY KEY,
  chat_id    BIGINT NOT NULL REFERENCES tg_pay_leads(chat_id) ON DELETE CASCADE,
  created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
  expires_at TIMESTAMPTZ NOT NULL,
  used_at    TIMESTAMPTZ
);

-- Журнал воронки: и для аналитики, и чтобы дожим не отправился дважды.
CREATE TABLE IF NOT EXISTS tg_pay_events (
  id       BIGSERIAL PRIMARY KEY,
  chat_id  BIGINT NOT NULL,
  user_id  INTEGER,
  kind     VARCHAR(32) NOT NULL,  -- start, claim, paid, nudge_<код>, consent, opt_out, blocked
  meta     JSONB,
  at       TIMESTAMPTZ NOT NULL DEFAULT now()
);
CREATE INDEX IF NOT EXISTS idx_tg_pay_events_chat_kind ON tg_pay_events(chat_id, kind);
```

`users.telegram_chat_id` (привязка алерт-бота) **не трогаем**: у него
уникальный индекс и своя логика отвязки. Связь с ботом оплаты живёт в
`tg_pay_leads.user_id`.

### 2. Бот `signals/pay_bot.py`

Копия каркаса `signals/alert_bot.py`:
- работает на хосте, long-poll `getUpdates`, под systemd `frame-pay-bot.service`;
- `TELEGRAM_API_ROOT` (релей в обход блокировок), `DB_URL` переписывается на
  `127.0.0.1`;
- ENV: `PAY_BOT_TOKEN`.

Команды и кнопки:

| Действие | Что делает |
|---|---|
| `/start <param>` | upsert в `tg_pay_leads` (start_param пишется только при первом входе), событие `start`, приветствие + кнопки |
| `[Выбрать тариф]` | URL `https://framedata.ru/pricing?src=tg_bot&feature=<param>&tgc=<token>`. Токен свежий на каждое сообщение, TTL 24 ч |
| `[Присылать скидки…]` | callback → `consent_marketing=true`, событие `consent` |
| `/stop` | `opted_out_at=now()`, больше никаких дожимов. Сервисные сообщения об оплате остаются |
| `/status` | если привязан: тариф и дата окончания; если нет: кнопка на тарифы |

`start_param`: только `[A-Za-z0-9_-]{1,64}` (ограничение Telegram), остальное
отбрасывается. Соглашение по именам кампаний: `p<номер поста>` (`p1812`),
`pin`, `bio`, `thor`.

### 3. API: привязка `POST /api/tg-pay/claim`

Новый роутер `api/routers/tg_pay.py`, только для залогиненного пользователя
(`get_current_user`).

- Вход: `{token}`. Токен найден, не истёк и не использован → `tg_pay_leads.user_id
  = user.id`, `linked_at`, `used_at`, событие `claim`.
- Если чат уже привязан к **другому** пользователю, перепривязываем на
  текущего: последний вход побеждает, так же, как в алерт-боте.
- Ответ всегда `{ok: true}`, даже если токен плохой. Это нужно, чтобы не
  раскрывать, существует ли токен.
- Rate limit, как у других auth-ручек.

### 4. Фронт

- `frontend/src/utils/purchaseSource.ts`: добавить `tg_bot` в `SOURCES`.
- `api/billing/source.py`: добавить `tg_bot` в `SOURCES`. Кампания едет в
  `source_feature` (до 64 символов), отдельная колонка не нужна.
- Захват `tgc`: при заходе на любую страницу с `?tgc=` сохранить токен в
  localStorage (TTL 24 ч), убрать параметр из адреса (`history.replaceState`).
  Как только пользователь залогинен, отправить `POST /api/tg-pay/claim` и
  удалить токен.
- Новых экранов нет.

### 5. Сообщение об оплате

Бот раз в минуту (в том же цикле, что и поллинг) ищет новые подписки
`status='active'` у привязанных лидов, по которым ещё нет события `paid`, и
пишет «Доступ открыт: <тариф> до <дата>». Правок в `api/billing/service.py`
нет, бот только читает `subscriptions`.

### 6. Дожимы

Отдельный cron на хосте `signals/pay_bot_nudges.py`, раз в 15 минут. Каждый
дожим отправляется не больше одного раза на лида (проверка по `tg_pay_events`).

| Код | Условие | Сообщение | Нужно согласие |
|---|---|---|---|
| `n1_noclaim` | старт > 24 ч, не привязан | «Остались вопросы? Вот что внутри» + кнопка | нет (ответ на его /start) |
| `n2_nopay` | привязан > 24 ч, активной подписки нет | напоминание + кнопка | нет |
| `n3_discount` | привязан > 72 ч, не оплатил | скидка на первую оплату | **да** |
| `n4_expiring` | подписка без автопродления кончается через 3 дня | «продлите» + кнопка | нет |
| `n5_renew_fail` | `renewal_last_error` не пуст | «не прошло продление, обновите способ оплаты» | нет |

Общие правила:
- не писать с 22:00 до 09:00 МСК;
- не больше 3 сообщений на лида за 7 дней;
- после `opted_out_at` или `blocked_at` (403 от Telegram) только `n5_renew_fail`
  и сообщение об оплате, и то только если не `blocked_at`;
- `n4` дублирует письмо из PR #1769, это нормально: каналы разные.

`n3_discount` требует механизма скидки на первую оплату. Сейчас
`subscriptions.discount_pct` работает только для retention-скидки к
рекуррентному списанию. Делается отдельным этапом (см. ниже).

### 7. Аналитика

Блок в `/admin/stats`: воронка `start → claim → paid` по `start_param` за
период, плюс выручка подписок с `source='tg_bot'`. Данные из `tg_pay_events`
и `subscriptions`.

### 8. Деплой

- `scripts/prod_deploy.sh`: перезапуск `frame-pay-bot`, так же, как у алерт-бота.
- systemd unit и cron-строка лежат в репо рядом со скриптом.
- `.env.example`: `PAY_BOT_TOKEN=`.

## Этапы (PR)

1. **Каркас бота**: миграция, `pay_bot.py` (/start, согласие, /stop, /status),
   systemd. Результат: бот отвечает, лиды копятся.
2. **Привязка и оплата**: `/api/tg-pay/claim`, захват `tgc` на фронте,
   `tg_bot` в источниках, сообщение «доступ открыт». Результат: полная воронка
   без дожимов.
3. **Дожимы** `n1`, `n2`, `n4`, `n5`.
4. **Воронка в /admin/stats.**
5. **Скидка на первую оплату** и `n3_discount`. Отдельно, после решения о
   размере скидки.

Этапы 1 и 2 можно выпустить вместе: по одному боту без привязки ничего не
измерить.

## Юридическое

- **406-ФЗ (авторизация).** Схема выше не авторизует через Telegram. Но уже
  есть `POST /api/auth/oauth/telegram` (Telegram Login Widget): регистрация
  через него выключена (`allow_registration=False`), а **вход для уже
  привязанных аккаунтов работает**. Это авторизация через Telegram, и она
  противоречит закону. Нужно решение: выключить (пустой `TELEGRAM_BOT_TOKEN`
  в API или убрать провайдер) или оставить на усмотрение юриста.
- **38-ФЗ ст. 18 (реклама).** Скидки и акции считаются рекламой, их можно
  слать только после явного согласия, поэтому есть кнопка `consent_marketing`.
  Сервисные сообщения (оплата прошла, продление не прошло, подписка кончается)
  согласия не требуют.
- **152-ФЗ.** В политику обработки ПДн добавить: Telegram user id, username,
  имя; цель: уведомления об оплате и предложения по подписке.
- Схему показать юристу до запуска этапа 3.

## Риски, которые проверить руками

- **Встроенный браузер Telegram.** URL-кнопка на телефоне открывается во
  встроенном браузере, сессии сайта там нет, и человек войдёт заново. Проверить,
  что вход через VK и Яндекс работает во встроенном браузере iOS и Android.
- **СБП из встроенного браузера.** После привязки счёта нужен переход в
  приложение банка (PR #1662). Проверить, что deeplink открывает банк из
  встроенного браузера Telegram. Если нет, показывать «Открыть в браузере».
- **Блокировки Telegram.** Бот ходит через `TELEGRAM_API_ROOT`, как и алерт-бот.
  Если релей упал, лиды не теряются (лежат в БД), но сообщения задержатся.

## Нужно от владельца до старта

1. Создать бота в @BotFather: имя, username, аватар, описание. Токен положить
   в `/opt/frame/.env` как `PAY_BOT_TOKEN`.
2. Тексты: приветствие (что даёт Фрейм за 3–4 строки), дожимы `n1`/`n2`.
   Могу набросать черновики.
3. Решение по входу через Telegram Login Widget (раздел «Юридическое»).
4. Размер и условия скидки для `n3`. Не блокирует этапы 1–4.
