# Граф владения: рёбра между эмитентами

Решает задачу, которую не решают ни вектора, ни поиск по словам: **новость про Озон
касается АФК Системы, потому что Система владеет Озоном.** Векторно эти новости далеки,
словами связь не выводится — нужно ребро.

Запрос Вадима 01.09.2026: «почему понизили кредитный рейтинг? возможно, АФК Система
владеет большой долей Озона… было бы классно расширить такие факты, чтобы выстроить
связи, понять причины и написать пост».

## ⚠️ Главный вывод проверки: не хватало не фактов, а РЕБРА

Вся цепочка уже лежала в `news_archive` на уровне абзацев:
```
04.06.2026  Система не продаёт Озон, переговоры со Сбером сорвались
30.06.2026  Система отдала Озон в ЗАЛОГ и получила кредит
24.08.2026  атаки БПЛА на логистику Озона: Озон −21%, Система −12%, Сегежа −9,5%
01.09.2026  АКРА понижает рейтинг АФК Системы, прогноз «негативный»
```
Система туда никогда не смотрела: ничто не связывало кандидата AFKS с новостями про OZON.

## Где хранится (готовая механика, ничего нового не нужно)

Таблица `world_facts`, `kind='связь'`. Миграция `061_world_facts_entity_links.sql`.
```sql
entities   = {AFKS,OZON}        -- ненаправленный набор участников, GIN-индекс
statement  = проза, направление живёт в тексте
valid_from / valid_until        -- окно действия (NULL = действует сейчас)
source / source_url / confidence
```
Читается в брифе через `_SELECT_ENTITY_LINKS` (`signals/content_ai.py`), плюс агент Шага В
может дёрнуть сам: `/api/internal/world-facts?as_of=ДАТА&entities=ТИКЕРЫ`.

**Почему не отдельная таблица и не граф-БД:** `world_facts` уже даёт набор участников,
окно действия, версионирование, источник и уверенность. Для вопроса «кто связан с AFKS»
направление не нужно, а дублировать механику версионирования — плохая сделка.

**Сейчас в базе 17 рёбер** (было 2 — AFKS–SGZH и AFKS–OZON из новостей). 03.09.2026
добавлены 15 рёбер владения со страниц акционеров: скрипт
`research/company_cards/ownership_edges.py` обходит вселенную, резолвит владельцев через
справочник эмитентов и раскладывает на три корзины — уверенные, неоднозначные и
не-эмитенты. В БД пишутся только уверенные, под ключом `own:ВЛАДЕЛЕЦ:ЦЕЛЬ`
(ключи `link:*` из новостей живут отдельно и не перезаписываются).

## Источник рёбер: страницы акционеров smart-lab (бесплатно)

`https://smart-lab.ru/q/{ТИКЕР}/shareholders/` — таблица «Держатель акции | % доли» плюс
строка «Дата последнего обновления этой структуры». Проверено на 14 бумагах, рёбра
эмитент→эмитент находятся сразу:

| компания | владелец | доля | обновлено |
|---|---|---|---|
| SGZH | АФК Система | 70,13 % | 30.05.2021 |
| MTSS | АФК Система | 42,09 % | 11.06.2026 |
| OZON | Система | 31,80 % | 27.07.2025 |
| SIBN | Газпром | 95,68 % | нет даты |
| MSNG | Газпром энергохолдинг | 53,85 % | 20.10.2022 |
| TGKA | Газпром энергохолдинг | 51,79 % | 05.07.2022 |
| ELFV | ПАО «ЛУКОЙЛ» | 80,49 % | 26.03.2026 |
| MRKU | Россети | 55,23 % | 13.08.2025 |
| RTKM | ВТБ 20,98 % + ВТБ 8,44 % | | 02.10.2023 |
| RUAL | EN+GROUP | 56,88 % | 19.08.2026 |

**Три ловушки:**
1. **Владельцы названы словами, не тикерами:** «Газпром энергохолдинг», «Система»,
   «ООО "РТ-Развитие бизнеса"(Ростех)». Резолвить через справочник эмитентов
   (`research/company_cards/`), не по подстроке: «Газпром» матчит и Газпром нефть.
2. **Даты снимков разные и старые** (2021–2026, у части нет вовсе). Дату хранить рядом с
   ребром обязательно, иначе агент выдаст устаревшую долю за текущую.
3. **Часть владельцев — не эмитенты**: Евтушенков, Севергрупп, Промышленные Инвестиции.
   Полезно для «кто за этим стоит», но это не ребро бумага→бумага.

⚠️ **Рёбра курируемые, не автоматические.** Проба автодобычи по тексту новостей дала мусор:
дочерняя компания почти никогда не названа тикером («дочерней компании Новатэка», «ООО
Башенная»). Автомат даёт СВИДЕТЕЛЬСТВА, ребро подтверждает человек. Точную долю не
выдумывать — помечать как незафиксированную, иначе модель заполнит пробел сама.

## Первоисточник по закону: существенные факты (714-П)

Положение Банка России 714-П от 27.03.2020. Нужная форма — **«о приобретении лицом права
распоряжаться определённым количеством голосов, приходящихся на голосующие акции»**
(глава 30; глава 44 — когда покупает сам эмитент или подконтрольная ему организация).

**Раскрывается при пересечении порогов: 5 %, затем 10, 15, 20, 25, 30, 50, 75, 95 %.**
Считается право распоряжаться прямо И косвенно через подконтрольные организации — то есть
цепочка Система → Озон попадает под раскрытие.

Полнее, но реже: годовой отчёт эмитента (владельцы свыше 5 % на дату), примечания к МСФО
(связанные стороны и состав группы), ЕГРЮЛ (для ООО), устав и проспект эмиссии.

## ⚠️ e-disclosure напрямую не парсится

Портал Интерфакса (`e-disclosure.ru`) — официальный центр раскрытия, но на запросы отдаёт
**заглушку с антибот-щитом ~364 КБ** вместо содержимого (проверено 03.09.2026). Плюс в
опыте ингеста справок о СЧА документирован бан по IP, из-за чего для части УК ходили на их
собственные сайты. Автоматический обход не строить: только браузером и руками, по сигналу.

## Как отслеживать изменения: три уровня

| уровень | источник | что даёт | режим |
|---|---|---|---|
| базовое значение | shareholders smart-lab | доля + дата снимка | раз в неделю, снимок с хэшем |
| **детектор** | `news_archive`, полнотекст | сигнал «доля могла измениться», с тикером | ежедневно, один SQL |
| подтверждение | существенные факты e-disclosure | юридический факт: кто, сколько, когда | вручную, по сигналу |

**Детектор уже работает — каналы ретранслируют раскрытия.** В архиве 290 сообщений с
формулировками существенных фактов: MarketTwits 162, «СМАРТЛАБ НОВОСТИ» 128. Часть —
дословный текст раскрытия («Сделки по голосующим акциям МГКЛ: существенного факта…»),
тикер уже размечен.

```sql
-- сигналы смены владения (2218 всего, ~180 за полгода)
SELECT posted_at::date, tickers, left(replace(text,chr(10),' '),150)
FROM news_archive
WHERE to_tsvector('russian', text) @@ to_tsquery('russian',
      '(долю | доли | пакет | акционер) & (продал | продаёт | купил | приобрёл | залог | выкуп)')
  AND tickers <> '{}'
ORDER BY posted_at DESC;

-- строго существенные факты
WHERE text ILIKE '%право распоряжаться%' OR text ILIKE '%голосующих акци%'
```

Индексы на `news_archive` под это уже есть: GIN по `tickers`, GIN по
`to_tsvector('russian', text)`, btree по `posted_at DESC`. Поиск по тикеру за 180 дней —
~20 мс на 487 тыс. строк. **Вектора для этой задачи не нужны** (см. ниже).

## Почему не вектора

Вектор отвечает на «что похоже», а нужно «кто с кем связан». Он не знает, что Система
владеет Озоном, — он знает лишь, что тексты похожи по словам. Новость про дроны на складах
Озона и новость про рейтинг Системы **векторно далеки**, а связь между ними есть.

Вектора в проекте есть, но для другого: подбор похожих ПОСТОВ как образцов стиля
(`research/content_pipeline_v2/retrieve.py`, model2vec + BM25 + RRF, корпус 1459 постов,
косинус на numpy без сервиса). Отдельная задача, где они оправданы, — «о чём вообще писали
вокруг этой даты», по архиву в 487 тыс. постов; там связи заранее неизвестны.

pgvector в БД не установлен (расширения: plpgsql, pg_stat_statements) и пока не нужен.
