# Акция, сложение сроков и повышение тарифа — контракт для фронта

Правила — `api/billing/sale.py`, применение — `service.checkout_offer`,
`assert_can_purchase`, `activate_from_webhook`. Тесты — `tests/test_sale_and_upgrade.py`.

## Включение акции (env API и orchestrator, затем recreate)

```
BILLING_SALE_CODE=bf2026
BILLING_SALE_TITLE=Чёрная пятница
BILLING_SALE_START=2026-11-27T19:00:00      # без пояса — московское время
BILLING_SALE_END=2026-12-04T19:00:00        # не включая; 7 дней
BILLING_SALE_PCT_BASIC=30                   # от цены 12 месяцев: 34 800 → 24 360 ₽
BILLING_SALE_PCT_PRO=45                     # 70 800 → 38 940 ₽
BILLING_SALE_GIFT_DAYS=30                   # «+1 месяц в подарок»; можно _BASIC / _PRO
# BILLING_SALE_MONTHLY=1                    # оставить месячные планы в продаже
```

Перед включением применить `db/migrations/123_sale_promo.sql`. Без миграции
акция не продаётся (лимит «раз на аккаунт» проверить нечем).

## `GET /api/billing/plans`

Добавлено поле `sale` (или `null`, если акции сейчас нет):

```
sale: { code, title, pct_max, starts_at, ends_at, monthly_available, eligible }
```

`eligible=false` — аккаунт по этой акции уже покупал, ему показывать обычные цены.
У годовой карточки тарифа при `eligible=true`:

```
yearly: { ..., amount,            // обычная годовая цена (она же цена продления)
          sale_amount,            // цена по акции
          sale_pct,               // процент на плашке
          sale_list_amount,       // зачёркнутая цена: 12 × месячная
          sale_gift_days }        // подарочные дни, 0 — нет
```

Если `sale.monthly_available=false`, месячные планы купить нельзя: сервер
ответит 400 «Во время акции … только годовую подписку».

## `GET /api/billing/checkout/preview?plan_id=…` (нужна авторизация)

Что клиент получит, оплатив сейчас. Показывать в окне оплаты ДО платежа.

```
{ plan_id, blocked,               // текст причины, если купить нельзя, иначе null
  amount, full_amount,            // к оплате сейчас / обычная цена плана
  promo_code, sale_title,
  starts_at, expires_at,          // срок: с учётом сложения, подарка и пересчёта
  bonus_days, bonus_from,         // дни за остаток младшего тарифа ('basic')
  gift_days,
  renew_amount, renew_at }        // сумма и дата следующего автосписания
```

Текст согласия на автосписание обязан называть `renew_amount` и `renew_at`,
а не акционную цену.

## Правила

- Скидка только на годовые планы; одна покупка по акции на аккаунт.
- Тот же тариф: новый срок прибавляется к концу оплаченного; подписчик с
  активным годовым планом может купить его же по акции.
- Basic → Pro: Pro начинается сразу, остаток Basic переводится в дни Pro
  (2 дня Basic = 1 день Pro, округление вверх), Basic закрывается. При
  возврате денег за Pro Basic восстанавливается.
- Basic, купленный при действующем отменённом Pro, начинается после Pro.
- Потолок: после покупки доступ оплачен не дальше чем на 3 года вперёд.
- Продление — всегда по обычной цене плана (`amount`).

## Защита от устаревшей цены

`POST /api/billing/checkout` и `POST /api/billing/sbp/bind` принимают
`expected_amount` — сумму, которую клиент видел на экране. Если сервер выставил
бы другую (акция началась или закончилась, лимит акции уже использован), ответ
409 «Цена изменилась…», платёж не создаётся. Фронт должен слать поле всегда и по
409 перезагружать `/plans`.

## Возврат к обычному виду после акции

Сервер перестаёт отдавать `sale` в `/plans` в момент `BILLING_SALE_END` — без
деплоя и без правки настроек. Баннеры, плашки, таймер и акционные карточки фронт
обязан показывать ТОЛЬКО при `sale != null`, тогда всё вернётся само. Купленные
по акции подписки не меняются: их срок и цена продления уже записаны.

## Переход с Pro на Basic одним окном (макет design/black-friday/7-switch-to-basic.html)

Подписчику Pro карточка Basic не блокируется: кнопка «Перейти на Basic» открывает
окно подтверждения. Данные для окна — `GET /checkout/preview?plan_id=basic_yearly&switch_down=true`:
`current` = `{ tier, title, expires_at, autorenew, is_higher }` (действующий Pro),
`starts_at` = день окончания Pro, `expires_at` = конец Basic.

Оплата — тот же `POST /checkout` (или `/sbp/bind`) с `switch_down: true`. Без
флага сервер ответит 400 «уже активен более высокий тариф». Автопродление Pro
выключается в момент оплаты, не при открытии формы: брошенная форма Pro не трогает.
