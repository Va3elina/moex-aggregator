# Свой бэктест-терминал — план (17.09.2026)

Рабочее имя: **Стенд**. Адрес: `framedata.ru/admin/backtest`, только админы.

## 0. Зачем и что считаем успехом

OsEngine отвергнут (интерфейс, эмулятор, Windows). TradingView не умеет портфель, наш ряд контрактов и ГО в рублях.
Нужен инструмент, который:

1. **Управляется Claude** — любое действие в интерфейсе = вызов API; всё, что видит Вадим, Claude может создать,
   запустить и прочитать без мышки.
2. **Реалистичен** — комиссии, ГО, стоимость шага, спред берутся из данных на дату сделки, а не константой.
3. **Выглядит как TradingView**, но с несколькими бумагами и окнами, как наша песочница.
4. **Считает то же, что робот** — один код правила у бэктеста и у робота на сервере.

Критерии приёмки первой версии (все проверяемы числом):
- Гибрид, 21 бумага, 1 контракт, без издержек → **3986 сделок**, совпадение с `hybrid_baseline.csv` 100 %.
- Гибрид, издержки «стакан + Трейдер» → **3801 сделка, +0.223 % на сделку** (H03 в lab).
- Самолёт, сентябрь 2026 → 331→326, 297→290, 279→267 (**+11.78 ₽**), как в OsEngine и TradingView.
- Счёт 1 млн, 6 слотов → в пределах ±0.5 п.п. от OsEngine (+19.7 % годовых, просадка −12.3 %).
- Живые сделки робота 16–17.09 (GZ, SR, SS) видны на том же графике поверх бэктеста.

### 2.2 Чего нет и как добываем

| параметр | меняется | источник «сейчас» | история |
|---|---|---|---|
| ГО биржи (INITIALMARGIN) | ежедневно, скачками в кризис | ISS `engines/futures/markets/forts/securities` | **в ISS нет** → копим сами с сегодня + реконструкция (ниже) |

| стоимость шага (STEPPRICE) | ежедневно у BR, PT, RI (в $) | ISS, T-Invest | реконструкция: шаг в $ × курс ЦБ на дату (курс у нас есть) |
| шаг цены, лот | редко | ISS | по контракту, хранить на контракт |
| биржевой сбор (BUYSELLFEE, ₽/контракт) | редко | ISS | копим; исторически — тарифы МосБиржи по датам |
| комиссия брокера | раз в год-два | PDF тарифов T-Bank | таблица тарифов с `valid_from` (Инвестор/Трейдер/Премиум, доп. список) |
| спред стакана | постоянно | Algopack obstats | **по дням** из obstats (у нас доступ есть) → таблица `bt_spread_daily` |
| лимиты цены (планки) | ежедневно | ISS HIGHLIMIT/LOWLIMIT | копим; для 2022 — важно (сделку по планке исполнить нельзя) |

**Итог этапа 0 (17.09.2026):**
- Поле IM (базовое ГО) в истории ISS — платный продукт «Итоги торгов»: 3750 ₽ за месяц данных, только с 01.2023
  (письмо МосБиржи 08.06.2026). Наш ключ Algopack его не открывает (проверено). 45 месяцев ≈ 169 тыс. ₽ — не берём.
- **Бесплатная замена найдена:** `iss/rms/engines/futures/objects/limits?date=` — ставки рыночного риска MR1/MR2/MR3
  по базовому активу **с 22.05.2018**, без авторизации. Базовое ГО ≈ расчётная цена × лот × MR1
  (17.09.2026: GAZR 0.17 ↔ ГО 17.5 %, Si 0.15 ↔ 14.9 %). Февраль 2022 виден: SBRF 0.23 → 0.40, Si 0.075 → 0.15.
  Выгрузка: `fetch_risk_rates.py` → `data/risk_rates.csv.gz`.
- Снимок всех 643 фьючерсов (ГО, стоимость шага, сбор, планки) копится на сервере с 17.09.2026:
  `/opt/hybrid-bot/specs_snapshot.py`, крон 09:10 и 19:10 МСК, файлы `/opt/hybrid-bot/specs/`.
- ГО брокера = базовое ГО × коэффициент (у T-Bank сейчас ≈ 1.0–1.05 к биржевому) — калибруем по снимкам.

Реконструкция исторического ГО (запасной путь, если ставок не хватит):
1. **Фаза 0 (день на исследование):** проверить, отдаёт ли МосБиржа историю ГО — страница контракта на moex.com,
   файлы риск-параметров НКЦ, Algopack. Если есть — грузим как есть.
2. Если нет — модель: `ГО(дата) = цена × лот × ставка(бумага, дата)`, ставка = сегодняшняя доля ГО в цене,
   умноженная на календарь известных повышений (февраль–март 2022: ×2–3; публичные релизы НКЦ).
   В отчёте всегда пометка «ГО: факт / модель» по каждой сделке.
3. Стресс-режим в интерфейсе: «ГО ×1.5 / ×2 / ×3» — проверка, пережил бы счёт повышение ГО.

### 2.4 Модель исполнения (настраивается в прогоне)
- Цена входа/выхода: `close свечи T` (как в базе spec7c) | `open следующей` (как OsEngine/TV) | `задержка N минут`
  (робот реально входит 17:15).
- Спред: нет | константа lab | **по дню из `bt_spread_daily`**; объём больше глубины стакана → штраф/урезание
  (ёмкость Самолёта ≈ 0.8 млн ₽).
- Комиссия: брокер (тариф на дату) + биржевой сбор; песочница 0.05 % — отдельный пресет для сверки с роботом.
- Счёт: капитал, слоты, целые контракты, ГО ≤ доля капитала, **ежедневный клиринг** (вариационная маржа),
  маржин-колл если equity < ГО (фиксируем событие, не молчим), планки (вход/выход по планке запрещён → перенос).
- Опционально: налог 13 %, доход на свободные деньги (ключевая ставка), абонплата тарифа.

## 3. Движок

Пакет `backtest/` (Python, без веб-зависимостей):
- `data.py` — чтение свечей и построение ряда V3 (перенос из `lab/data.py`, `lab/engine.series`): ближний контракт,
  монотонная цепочка, ночь ролла выброшена, разрыв ≤ 4 дней, будни, ≥ 60 баров. Кэш parquet в томе воркера,
  инвалидация по `max(begin_time)`.
- `rules.py` — **декларативное правило (JSON)**. Семейство «сессионных» стратегий покрывает всё, что мы исследовали:
  ```json
  {"signal": {"from": "10:30", "to": "17:00"},
   "long":  {"type": "quantile", "of": "ups",   "q": 0.67, "window": 250, "min_obs": 100},
   "short": {"type": "quantile", "of": "downs", "q": 0.90, "window": 250, "min_obs": 100},
   "filters": [{"type": "straightness", "min": 0.58, "points": ["10:00","11:30","13:00","14:30","16:00","17:15","18:30"]}],
   "entry": {"at": "17:00", "delay_min": 15}, "exit": {"at": "11:00", "next_day": true, "delay_min": 10}}
  ```
  Гибрид, Алгозавр (`{"type":"fixed","value":0}` / `-0.02`), Прямой ход v2 — три пресета одного формата.
  Новое правило этого семейства = новый JSON → **без деплоя**, Claude создаёт его вызовом API.
- `strategies/*.py` — для всего, что не влезает в JSON (стопы, индикаторы, пары): класс с `params` (как `input.*` в Pine,
  из них интерфейс сам строит форму) и `on_bar()`. Добавляются через PR.
- `engine_points.py` — быстрый векторный движок по дневным точкам (как lab; 21 бумага × 7 лет < 2 с).
- `engine_bars.py` — событийный по 5-мин свечам (стопы, внутридневной контроль ГО, планки). Фаза 3.
- `account.py` — слоты, целые контракты, ГО, клиринг, комиссии, спред.
- `metrics.py` — годовых, просадка, Шарп, Сортино, винрейт, профит-фактор, по годам/бумагам/сторонам,
  DSR/PBO, плацебо, срез хвостов (перенос из `lab/checks.py`), устойчивость к задержке.
- `tests/` — 24 теста lab переезжают + приёмочные числа из раздела 0. CI гоняет их на каждом PR (быстрые, на фикстурах).

Воспроизводимость: у прогона `engine_version` (git sha) + `data_hash`; одинаковый spec + данные = одинаковый результат.
Замороженные spec7/7b/7c — пресеты «только чтение».

## 4. Управление Claude

Правило проектирования: **в интерфейсе нет ни одного действия, которого нет в API.**

REST `/api/admin/bt/` (все под `require_admin`):
- `POST runs` (spec) → id; `GET runs`, `GET runs/{id}` (статус, метрики), `DELETE`, `POST runs/{id}/cancel`
- `GET runs/{id}/trades|equity|signals` (фильтры: бумага, даты, сторона), `GET runs/{id}/export.csv`
- `POST compare` (несколько run_id → таблица метрик и общая кривая)
- `GET/POST/PUT rules` (библиотека правил), `GET strategies` (питоновские + схема параметров)
- `GET candles?st=SS&from&to&tf=5|15|60|D` (склеенный ряд + метки ролла), `GET specs?secid&d` (ГО/шаг/сборы на дату)
- `GET live/trades` (сделки робота), `GET data/status` (докуда есть свечи, снимки ГО, спреды)
- `GET/PUT workspaces/{name}` — раскладка окон. **Claude может собрать Вадиму рабочее пространство**
  («Самолёт: гибрид против Алгозавра, сентябрь») и дать ссылку `/admin/backtest?ws=…`.
- `POST sweeps` — сетка параметров (по сути оптимизатор) с обязательным out-of-sample разрезом и счётчиком
  «сколько вариантов перебрано» (защита от подгонки — идёт в DSR).

Доступ Claude:
1. **CLI** `python -m backtest.cli run|status|trades|compare|rule …` — на сервере по SSH (`docker exec bt-worker …`),
   без HTTP-авторизации. Основной путь, работает уже в фазе 1.
2. REST с сервисным ключом `BT_SERVICE_KEY` (заголовок; только `/api/admin/bt/*`, только с IP-списка/локально) — фаза 2.
3. Проверка глазами — Browser-инструмент на `/admin/backtest?ws=…` (скриншот в чат).
4. (позже) MCP-сервер поверх того же REST, если захочется вызывать из любых сессий.

Скилл `.claude/skills/moex-backtest-stand/` + агент — чтобы следующая сессия умела этим пользоваться без раскопок.

## 5. Интерфейс

Роут `/admin/backtest`, lazy, без Layout сайта, своя тема (тёмная, в духе TradingView/нашей песочницы).

**Каркас:** верхняя панель (рабочее пространство, прогон, период, кнопка «Запустить», статус данных) · левая панель
(бумаги с галочками и мини-результатом по каждой) · центр — **окна** · правая выдвижная панель настроек прогона.

**Окна** (перетаскивание, ресайз, «выстроить встык», сохранение раскладки — поведение как в `/sandbox`):
оконный менеджер пишем отдельным модулем `pages/backtest/wm/` (логику песочницы не трогаем и не импортируем —
там монолит 1244 строки; берём подход, не код). Каждое окно = {тип, бумага, прогон(ы), свои настройки}.

Типы окон:
1. **График** — свечи 5м/15м/1ч/День (агрегация на бэке), метки ролла, стрелки вход/выход, линия сделки
   (зелёная/красная), подсветка окна сигнала 10:30–17:00, плашка «ход −5.6 % / порог −3.9 %». Наведение на сделку —
   карточка (объём, ГО, комиссия, спред, ₽). Клик по сделке в списке — график прыгает к ней.
   Слои: бэктест A, бэктест B (сравнение правил), **живые сделки робота**, пропущенные сигналы (серые метки с причиной).
2. **Капитал** — кривая, просадка под ней, загрузка ГО (% капитала), несколько прогонов наложением, бенчмарк
   (MX buy&hold, депозит по ключевой).
3. **Сделки** — таблица как «Список сделок» TV + наши колонки (ГО, комиссии, спред, причина), фильтры, сортировка, CSV.
4. **Сводка** — метрики, по годам, по бумагам, лонг/шорт, распределение сделок, месячная тепловая карта.
5. **Сигналы** — журнал решений по дням: все 21 бумага, ход, пороги, что сделали и почему нет.
6. **Сравнение** — 2–4 прогона рядом: метрики, разница по сделкам (какие есть у одного и нет у другого).
7. **Проверки** — батарея lab: плацебо, DSR/PBO, половины истории, срез хвостов, чувствительность к задержке и к ГО×k.
8. **Реализм** — для бумаги: график ГО, стоимости шага, спреда во времени, пометка «факт/модель».
9. **Робот** — журнал живого счёта, расхождение «робот против бэктеста на те же дни» (слиппедж, опоздания).

**Настройки прогона** (форма строится из схемы правила/стратегии): правило → бумаги → период → счёт (капитал, слоты,
режим объёма, лимит ГО) → издержки (тариф, спред, стресс ГО) → исполнение (цена, задержка). Пресеты:
«как spec7c», «как OsEngine», «как робот в песочнице», «как TradingView (1 контракт, 0.04 %)».

Синхронизация окон: общий курсор времени и «связка по бумаге» (цветные группы, как в TV) — сменил бумагу в одном
окне, связанные переключились.

Состояние: URL (`?ws=&run=`) + `bt_workspaces` в БД; локально — только мелочи.

- **Истории ГО может не быть нигде** → модель + стресс-тест + честная пометка; своё копим с первого дня.
- **Память сервера (8 ГБ)**: воркер с лимитом, движок по точкам лёгкий; событийный — по одной бумаге за раз, parquet-кэш.
- **Подгонка**: удобный терминал провоцирует перебор. Счётчик вариантов, out-of-sample по умолчанию, замороженные spec
  нельзя редактировать, DSR в сводке.
- **Расползание сайта**: всё в `pages/backtest/` и `api/routers/admin_bt.py`; правки общих компонентов — только
  необязательные пропсы + проверка responsive-аудитором, что сайт не изменился.
- **Лицензия МосБиржи**: данные видит только админ — внутреннее использование, не распространение.
- **Безопасность**: JSON-правила не исполняют код; питоновские стратегии — только из репозитория через PR.
