# Стенд — свой бэктест-терминал

Страница `/admin/backtest` (только админы) · API `/api/admin/bt/*` · расчёт — контейнер `bt-worker` · план — [PLAN.md](PLAN.md).

```
браузер ──► api (admin_bt.py): кладёт прогон в bt_runs, читает bt_* ──► Postgres
                                                                         ▲
bt-worker (python -m backtest.worker, лимит 1.5 ГБ): очередь → движок → bt_signals / bt_trades / bt_equity
```
API ничего не считает. В интерфейсе нет действия, которого нет в API или командах — терминалом может управлять агент.

## Страница (версия 2, 17.09.2026)
Устройство как у TradingView: тонкая шапка (бумага с логотипом и поиском · таймфрейм · индикаторы · `{ }` редактор
стратегии · «Вид»: слои графика и сетка 1/2/4), графики, снизу «Тестер стратегий» (обзор блоками, список сделок,
журнал решений, сравнение прогонов). Вся аналитика тестера считается в браузере (`stats.ts`) — срез «бумага / весь
счёт» мгновенный. Состояние интерфейса — `usePrefs.ts`: localStorage + раскладка `default` на сервере
(`bt_workspaces`); агент может собрать раскладку и дать ссылку `/admin/backtest?ws=<имя>`.
Свечи грузятся кусками по календарным границам (месяц / квартал / год) и кэшируются в Redis; история догружается
при прокрутке влево. Сделки робота — `GET /live/trades` (журнал `/opt/hybrid-bot/state`, смонтирован только для чтения).

## Команды (на сервере)
```
docker compose exec bt-worker python -m backtest.cli submit --rule hybrid7c --exec robot --name "гибрид как робот"
docker compose exec bt-worker python -m backtest.cli runs
docker compose exec bt-worker python -m backtest.cli show 12 --trades SS --last 10
docker compose exec bt-worker python -m backtest.cli data status | pull
journalctl -t frame-bt-worker -n 50
```
Прогон из `submit` виден на странице: `/admin/backtest?run=<id>&st=SS`.

## Устройство
- `store.py` — кэш 5-мин свечей всех контрактов 22 типов фьючерсов (pickle в томе `bt_data`), докачка из `candles`.
  Цена «в T» = закрытие свечи, начавшейся в T.
- `rules.py` — правило как JSON: окно сигнала, порог лонга/шорта (квантиль прошлых дней или число), фильтр прямоты,
  цена и задержка входа/выхода. Пресеты: `hybrid7c`, `algozavr`, `straight_v2`. Новое правило = JSON в `POST /runs`.
- `engine.py` — ряд V3 (ближний контракт, монотонно, ≥ 60 свечей, будни; ночь только если завтра тот же контракт и
  разрыв ≤ 4 дней) → журнал решений → сделки.
- `costs.py` — тарифы T-Bank за сторону с датой действия; спред стакана за круг (`data/costs.json`, Algopack obstats).
- `account.py` — счёт в рублях: капитал/слоты на сделку, целые контракты, ГО, комиссия и спред списываются сразу.
  ГО `mr1` — историческое: стоимость контракта × ставка рыночного риска МосБиржи на дату (`data/risk_rates.csv.gz`,
  с 22.05.2018; бесплатный ISS `rms/engines/futures/objects/limits`; обновление — разовое, `research/backtest_terminal/fetch_risk_rates.py`).
- `runner.py` — один прогон по spec; `worker.py` — очередь; `cli.py` — команды.
- `tests/` — приёмочные числа (нужен кэш свечей; в CI пропускаются): база spec7c 3800/3801, +0.223 % на сделку,
  Самолёт 09.2026 как в OsEngine и TradingView, 3949 сигналов, счёт OsEngine воспроизводится с точностью 1.5 %.

## Стратегии заявками (26.09.2026)
`MODE = "orders"` в коде на Python → `backtest/orders.py`: `on_bar(i, b, s, p)` ставит заявки как `strategy.entry` /
`strategy.exit` в Pine — объём в контрактах, лимитки, стопы, доборы (`PYRAMIDING`), выход по средней. Исполнение — как
эмулятор брокера TradingView (заявка со свечи i работает с i+1; путь open→ближний экстремум→дальний→close; лимитка — по
своей цене или по открытию при гэпе). Счёт считается там же, свеча за свечой, по одной бумаге: комиссия тарифа, спред
только у рыночных и стоп-заявок, ГО на дату (вход без свободного ГО снимается, капитал < ½ ГО → брокер закрывает всё),
`go: tv100` — маржа 100 % и маржин-колл ×4, как в TradingView v6 по умолчанию. Фандинг вечных фьючерсов —
`data/funding.csv.gz` (ISS SWAPRATE, разово: `data/fetch_funding.py`), с позиции, дожившей до клиринга 18:50.
Бумага **CNYRUBF** (вечный юань): ГО по ставке UCNY (8 %, до 02.2023 — CNYRUBTOM), спред — оценка (в obstats его нет).
Пример в редакторе — «DCA-мартингейл (заявки, как в Pine)»; тесты — `tests/test_orders.py` (без кэша свечей).
**Перенос через экспирацию (27.09.2026):** на смене квартального контракта позиция и заявки переезжают в новый
(`pyengine.roll_gaps`: цена нового − цена старого в ту же минуту; цены входа сдвигаются, перенос = 2 комиссии и 2 полуспреда;
`ROLL = False` — закрывать). Вечные фьючерсы в Стенде: CNYRUBF, USDRUBF, EURRUBF, GLDRUBF, IMOEXF, SBERF, GAZPF (фандинг,
ГО по ставкам риска, сверенным с ISS INITIALMARGIN). `s.point_value` — ₽ за 1.0 цены (объём от капитала). Пример
«DCA-сетка под волатильность» (шаг и тейк в долях дневной волатильности, сетка = капитал × lev) — им сделан перебор
research/dca_martingale/screen.py по всем бумагам и годам.
Сверка с эталоном (research/dca_martingale): тот же Pine-мартингейл на 5-мин свечах 06–09.2026 с маржой 100 % —
103 сделки / +73.7 тыс. ₽ против 102 + открытая позиция / +73.9 тыс. (разница — комиссия закрытия хвоста).
