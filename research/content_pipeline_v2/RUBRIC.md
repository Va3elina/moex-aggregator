# Рубрика оценки черновика (v1, 31.08.2026)

Основание: [RESEARCH_2026-08-31.md](RESEARCH_2026-08-31.md) §2, [PLAN.md](PLAN.md) Фаза 2.

## Зачем рубрика, а не правила в промпте

Правила Шага В накапливались по одному после каждого плохого поста и доросли до
~13 тыс. знаков. Рубрика — то же знание, но вынесенное **из генератора в оценщик**:
писатель получает короткий промпт, а соблюдение проверяется отдельно и измеримо.
Тогда любое изменение промпта можно сравнить с предыдущим, а не угадывать.

**Все пункты бинарные** (да/нет). Это не упрощение: LLM плохо калибруют тонкие
градации, и бинарные критерии дают устойчиво более надёжные оценки, чем шкалы 1-10.

## Как считается итог

Итоговый вердикт выводится **кодом, а не моделью** — модель только заполняет пункты.
Так вердикт воспроизводим и его видно, из чего он собран:

- провал **любого** пункта группы A (фактура) → `брак`;
- иначе провал 2+ пунктов групп B/C → `брак`;
- иначе провал 1 пункта B/C → `спорно`;
- ни одного провала → `годится`.

Собственный вердикт модели тоже пишется в результат — расхождение кодового и
модельного вердикта само по себе сигнал, что рубрика сформулирована плохо.

## Группа A — фактура. Любой провал = брак

| ключ | пункт проходит, если |
|---|---|
| `numbers_traceable` | каждое число, процент, дата и объём в посте находится в брифе |
| `no_invented_facts` | нет утверждений об истории компании, рынка или прошлых аналогиях, которых нет в брифе |
| `no_self_contradiction` | пост не противоречит сам себе и брифу — в частности, направление позиции согласовано с перекосом net/gross (положительный перекос = чистый ЛОНГ, отрицательный = чистый ШОРТ) |
| `time_arrow_ok` | если сигнал ОИ датирован не раньше новости, пост НЕ утверждает, что позицию набирали до новости / знали заранее |

## Группа B — смысл

| ключ | пункт проходит, если |
|---|---|
| `has_thesis` | есть один внятный тезис, а не перечисление фактов |
| `link_earned` | связь новости и сигнала заявлена не сильнее, чем позволяют данные; нет каузальности там, где есть только совпадение |
| `conclusion_concrete` | вывод называет конкретный вероятный сценарий с хеджем («часто приводит к развороту»), а не отделывается голым «стоит последить» |
| `no_redundancy` | нет предложений и абзацев, пересказывающих уже сказанное; нет списка чужих тикеров, который тут же сам дисклеймится |

## Группа C — голос и формат

| ключ | пункт проходит, если |
|---|---|
| `format_ok` | есть подпись `😀😀😀/@FrameTool` и хэштег `#открытыйинтерес`; абзацы начинаются с ◽️; тире одинарное `-`; нет маркдауна и капса |
| `no_methodology_talk` | нет языка методологии: «сильнее обычного дневного шага», z-score, ATR, «к обычному дневному шагу» |
| `length_ok` | 400-1200 знаков |
| `numbers_sparse` | не больше двух чисел на абзац |

## Известные ограничения v1

- **Набор мал (23 примера) и смещён.** Все черновики — с 15.07 по 06.08.2026, из них
  большая часть по 4 тикерам (GAZP, VKCO, RGBI, SBER).
- **Метка `published` ненадёжна** — публикация шла в ТЕСТОВЫЙ канал (подтвердил Вадим
  31.08), одобрение могло означать «механизм работает», а не «пост хороший». Двое из
  пяти (559, 722) содержат выдуманные факты и не имеют подписи.
- **`duplicate_event` в рубрику НЕ входит** намеренно: дубль нельзя увидеть внутри
  одного текста, это свойство пары черновиков. Проверяется отдельно, кодом, по
  (дата, тикер, сигнал).
- **`length_ok` и `numbers_sparse`** считаются и кодом тоже — там, где правило
  механическое, модель не нужна. Оставлены в рубрике для сверки: расхождение
  кода и модели показывает, насколько судья вообще внимателен.
