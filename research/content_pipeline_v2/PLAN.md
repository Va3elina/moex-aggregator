## Фаза 1 — починить обратную связь (Н1)

**Зачем:** сейчас правка человека затирает черновик ИИ, а причина отказа не
пишется никуда. Это корень раздутого промпта. Без этого Фаза 2 не сможет расти.

1. `db/migrations/054_content_candidates_feedback.sql`
   - `draft_text_ai TEXT` — оригинал ИИ, пишется один раз на Шаге В, **никогда
     не перезаписывается**;
   - `reviewer_reason TEXT` — свободный текст «почему отклонил / что правил»;
   - `reviewer_reason_code VARCHAR(32)` — код из фиксированного списка, для
     статистики (список ниже, финализируется после разметки Фазы 2).
2. `api/routers/content_news.py` — `step-c` PATCH пишет в **оба** поля
   (`draft_text` и `draft_text_ai`).
3. `signals/content_review_bot.py`
   - «Править» — оригинал уже сохранён в `draft_text_ai`, ничего не теряем;
   - «Отклонить» — второй экран с кнопками-кодами причин + возможность вписать текст;
   - «Одобрить» после правки — тоже фиксируем `reviewer_reason` (что правил),
     диффы считаются автоматически из пары `draft_text_ai` / `draft_text`.
4. Kanban `/admin/content-news` — показать дифф ИИ↔финал. Не блокер, можно позже.

**Предварительный список кодов причин** (уточнить по факту разметки):
`натянутая связь` · `стрелка времени` · `вода в выводе` · `дубль абзацев` ·
`нарушен формат` · `выдуманный факт` · `методологический язык` · `слишком длинно` ·
`новость не стоит поста` · `неверная терминология (net/gross)`

**Готовность:** миграция применена на проде, код задеплоен, ничего не запущено.

## Фаза 2 — eval-набор + судья с бинарной рубрикой (Н2)

**Зачем:** до этого шага мы не можем отличить улучшение промпта от ухудшения.

1. **Разметка.** Я делаю первый проход по 23 примерам (гипотеза приговора +
   какие пункты рубрики нарушены), Вадим подтверждает/правит. ⚠️ Требует Вадима.
2. **Рубрика** — ~10 бинарных пунктов (да/нет; бинарные критерии надёжнее шкал 1-10):
   - есть один внятный тезис, а не набор фактов;
   - каждое число трассируется в строку брифа;
   - стрелка времени не развёрнута;
   - вывод конкретен (называет сценарий), а не «стоит последить»;
   - нет аналогии, которой нет в брифе;
   - нет абзацев, повторяющих друг друга;
   - нет языка методологии («сильнее обычного дневного шага»);
   - терминология net/gross корректна;
   - формат: подпись, хэштег, одинарное тире, нет маркдауна;
   - длина в целевом коридоре.
3. **Судья.** Прогон **локально через `claude -p`** (headless Claude Code, версия
   2.1.232 стоит) — подписка Вадима, **ключ API не нужен**, гео-блока в Берлине нет,
   релей не нужен. Инфраструктурных блокеров у этой фазы нет.
4. **Метрика — согласие судьи с приговорами Вадима.** Пока согласие низкое, правим
   *рубрику*, а не промпт. Только когда судья воспроизводит человеческие решения,
   он становится инструментом.
5. `eval.py` — прогнать N вариантов промпта по набору, вывести таблицу
   «вариант × пункт рубрики × попадание» + согласие с человеком.
6. **Первая гипотеза для проверки на наборе:** предсказывает ли
   `signal_minus_news_days` брак (§1.1a). Если да — Фаза 3 начинается с рамок сюжета.

**Только после этой фазы** правила переезжают из промпта в рубрику судьи, и
промпт худеет под метрику, а не на глазок.

## Фаза 3 — разделить роли (Н3)

Сейчас Шаг В одновременно решает, есть ли сюжет; выбирает угол; выбирает структуру;
пишет; сам себя фактчекает; сам себя редактирует по стилю.

1. **Починить бриф (не промпт!).** В payload Шага В добавить явное поле рамки:
   `упреждение` (сигнал раньше новости) / `реакция` (позже) / `совпадение`.
   Лечит 30% брака из §1.1a в том месте, где порядок дат известен точно —
   `signals/content_match.py` / `_step_c_payload`.
2. **Шаг Б2 «редакционный угол»** (дешёвый вызов): «сформулируй одной строкой тезис —
   что здесь новость и почему это интересно. Нет тезиса → стоп». Отказ становится
   дешёвым и структурным, а не героическим решением писателя.
3. **Шаг В — писатель.** Короткий промпт. Число абзацев = число утверждений в
   тезисе, а не подражание образцам.
4. **Шаг Г — редактор.** Отдельная роль, правит по рубрике Фазы 2, не пишет с нуля.

**Решение, которое нужно принять до начала:** остаёмся на Claude Routine (каждый
шаг = отдельный облачный триггер: свой промпт в UI, свой токен, логов нет,
fire-and-forget) или переносим шаги в host-скрипт через прямой Anthropic API
(релей уже форвардит `/anthropic/*`, но пробрасывает только `authorization` —
для `x-api-key` нужна однострочная правка воркера). Три роли на Routine = три
триггера и три промпта, которые нельзя прогнать по eval-набору.

## Фаза 4 — второй мозг (Н4)

**(а) Мир / макро.** Датированные факты с провенансом и сроком годности: ставка ЦБ,
инфляция, санкционный режим, нефть/газ, ключевые политические сюжеты. Отдаётся в
бриф **только с causal masking** — факты с датой ≤ даты новости. Начинать с плоского
датированного дайджеста; temporal knowledge graph — когда факты начнут конфликтовать.
Заменяет «железное правило фактуры»: факты можно брать из хранилища (с провенансом),
из памяти модели — нельзя.

**(б) Корпус постов.** Все посты канала с метаданными (тип события, число абзацев,
длина, тезис) → динамические few-shot: 2-3 ситуативно похожих поста вместо 4
статичных. Корпус обязан быть **разнообразным по структуре**, иначе мы заменим один
шаблон другим.
⚠️ **Блокер:** экспортов Telegram локально нет — прошлые (`~/Downloads/ChatExport_2026-07-13`)
удалены. Нужен свежий экспорт @FrameTool. Требует Вадима.
