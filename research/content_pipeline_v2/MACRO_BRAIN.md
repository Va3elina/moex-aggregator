# Второй мозг: макро и геополитика — исследование (31.08.2026)

Задача Вадима: «макро узлы надо запустить исследование — может есть готовые проекты,
источники или мысли как это сделать».

## Что есть готового

### Мировые событийные базы
| проект | что даёт | пригодность нам |
|---|---|---|
| [GDELT](https://gdeltcloud.com/) | каталог мировых новостей, 100+ языков, сущности/темы/тональность, бесплатно без квот | ⚠️ высокая полнота, но «ожидает от вас реальной инженерной работы»: сырьё, а не факты. Документация разбросана, порог входа высокий |
| [POLECAT / htkgh-polecat](https://arxiv.org/abs/2601.00430) | геополитические события как гипер-реляционный **временной граф знаний**, готовый датасет + бенчмарк LLM | академический, англоязычный, про межгосударственные события — не про эмитентов MOEX |
| [ACLED, UCDP](https://www.worldmonitor.app/blog/posts/free-geopolitical-data-apis-2026/) | конфликты, академическая разметка, free API | узкая тема, к рынку РФ отношение косвенное |
| [Global Macro Database](https://www.globalmacrodata.com/) | 46 показателей, 239 стран, 160 источников, свободно для некоммерческого | ⚠️ **некоммерческая лицензия** — у нас платный сервис, не подходит |

### Санкции — единственная тема, где готовое реально годится
| проект | что даёт |
|---|---|
| [OpenSanctions](https://www.opensanctions.org/) | открытая БД санкций/PEP, 460 источников, машиночитаемо |
| [OFAC Sanctions List Service](https://ofac.treasury.gov/sanctions-list-service) | официальные списки + **архив delta-файлов по годам** — то есть история изменений, а не только срез «сейчас» |

Архив дельт у OFAC — ровно то, что нужно для фактов со сроком годности: можно
восстановить, что было верно на дату новости, а не только что верно сегодня.

### Российские источники
- [ЦБ РФ, сервис получения данных](https://www.cbr.ru/statistics/data-service/) — API по показателям;
- [ЦБ РФ, календарь публикаций](https://www.cbr.ru/statistics/indcalendar/) — когда что выйдет (готовый источник ожидаемых событий);
- [Росстат, открытые данные](https://rosstat.gov.ru/folder/12793) и [ФГБУ ГМЦ, API «Мультистат»](https://www.gmcgks.ru/720);
- [Cbonds](https://cbonds.ru/rosstat-indexes/) — уже в наших источниках, 30 категорий данных Росстата.

### Форма хранения
[Zep / Graphiti](https://arxiv.org/abs/2501.13956) — временной граф знаний: у каждого
факта время начала, время окончания и происхождение; при изменении старый факт
инвалидируется, и агент не выбирает между устаревшим и текущим.
[LLM4Geopolitics](https://onlinelibrary.wiley.com/doi/10.1111/exsy.70258) — связка
доменной модели с RAG поверх структурированного графа.

## Вывод по готовому: прямого решения нет, и брать GDELT не надо

Всё готовое — либо про межгосударственную политику (нам нужен рынок РФ и конкретные
эмитенты), либо сырьё, требующее собственного слоя извлечения фактов, либо с
несовместимой лицензией. Единственное, что стоит взять как есть, — **санкции**
(OpenSanctions/OFAC с историей дельт) и **календарь ЦБ**.

## ⭐ Главная мысль: сырьё для второго мозга у нас УЖЕ ЕСТЬ, и мы его выбрасываем

Конвейер прожевал **932 новостных кандидата и выбросил 850**. Каждый из них — это
датированное событие с источником, прошедшее через ИИ-оценку значимости. Мы
используем их один раз, как повод для поста, и удаляем.

При этом ровно этот поток и есть то, чего не хватает генератору: «что сейчас
происходит». Не нужен GDELT, чтобы узнать про указ, санкционный пакет или заявление
ЦБ — это уже пришло к нам через MarketTwits и Smartlab и было отброшено, потому что
не годилось для поста ПРО ТИКЕР.

Плюс структурные показатели (ставка, инфляция, M2, ВВП, цены, ОИ) у нас **уже лежат
в своей БД** — их не надо ниоткуда тянуть.

## Предлагаемая конструкция

**Не граф на старте.** Плоская таблица `world_facts`, узлы появятся, когда факты
начнут противоречить друг другу:

| поле | смысл |
|---|---|
| `statement` | факт одной фразой, человеческим языком |
| `kind` | ставка / инфляция / санкции / геополитика / эмитент / сырьё |
| `entities` | тикеры, страны, компании |
| `valid_from`, `valid_until` | срок годности; `valid_until IS NULL` = действует |
| `source_url`, `confidence` | происхождение и уверенность |
| `superseded_by` | какой факт его отменил |

**Наполнение — три канала:**
1. **Из своего же новостного потока** (главный): дешёвый шаг «это разовый шум или
   факт со сроком годности?» на кандидатах, которые сейчас просто отбрасываются.
   932 кандидата за три недели — это ~44 факта в день на входе.
2. **Из структурных источников**: ЦБ (ставка, инфляция, календарь), Росстат/Cbonds.
   Уже есть свои фетчеры.
3. **Санкции**: OpenSanctions / OFAC delta-архив.

**Выдача — с обязательной отсечкой по времени:**
```sql
WHERE valid_from <= :news_date
  AND (valid_until IS NULL OR valid_until >= :news_date)
```
Без неё получим ровно ту ошибку, что дала пост 845: факт из будущего, поданный как
известный на момент события. Это НЕ то же, что векторный поиск: вектор вернёт
«похожее», а нам нужно «действовавшее на дату». Поэтому макро — узлы с датами, а не
эмбеддинги.

## Чего делать НЕ надо

- **Не тащить GDELT.** Полнота там мировая, а нам нужна глубина по одному рынку;
  инженерная цена несопоставима с пользой.
- **Не начинать с графа.** Плоская таблица с `valid_from`/`valid_until` покрывает
  почти всё; граф оправдан, когда понадобится связывать факты между собой.
- **Не брать Global Macro Database** — некоммерческая лицензия, у нас платный сервис.
- **Не хранить макро в векторах.** Вопрос к этой базе — «что было верно на дату»,
  а не «что похоже».
