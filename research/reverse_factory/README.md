# Завод обратного инжиниринга торговых стратегий

Берёт чужую стратегию (трейдер копитрейдинга, стратегия invvo, выгрузка TradingView) и отвечает:
**что это за тип, когда входит, как выходит, на чём зарабатывает, чем рискует, можно ли повторить.**
Каждый прогон оставляет отчёт, паспорт и строку в реестре; выводы копятся в [KNOWLEDGE.md](KNOWLEDGE.md).

Запущен 26.09.2026 по итогам ручного разбора Meridian, Syndicate, Algotoria, мартингейлов HYPE/ONDO/DOGE
(см. `research/crypto_btc/copytrade/`). Проверка завода — он повторяет ручные выводы (раздел «Калибровка» в KNOWLEDGE.md).

## Как пользоваться

```bash
cd research/reverse_factory
.venv/bin/python run.py add invvo 16                    # стратегия invvo по номеру (полная история + кривая)
.venv/bin/python run.py add invvo all                   # все стратегии invvo
.venv/bin/python -m factory.receiver &                  # приёмник выгрузок из браузера → inbox/ (127.0.0.1:8765)
.venv/bin/python run.py bybit-bundle-js "slug=leaderMark;slug2=mark2" --name b.json > inbox/b.js   # скрипт пакета
#   → выполнить текст inbox/b.js во вкладке https://www.bybit.com/copyTrade/ (javascript_tool); вкладка уйдёт на приёмник
.venv/bin/python run.py add bybit-bundle inbox/b.json   # разложить пакет и разобрать каждого
.venv/bin/python run.py add tv inbox/trades.csv --name "Моя стратегия" --sym BTCUSDT [--tz 3]
.venv/bin/python run.py add csv f.csv --name X --map sym=..,side=..,p_open=..,p_close=..,t_open=..,t_close=.. [--time-unit s]
.venv/bin/python run.py analyze <slug> [--tf 360] [--skip entry,replicate,exits]   # перепрогнать
.venv/bin/python run.py analyze-all                     # перегнать ВСЕ цели на текущем коде (после любого улучшения завода)
.venv/bin/python run.py registry                        # все разобранные цели одной таблицей
```
Окружение: `python3 -m venv .venv && .venv/bin/pip install pandas numpy scipy scikit-learn matplotlib pyarrow tabulate`.

**Bybit — только через браузер** (Akamai режет curl, даже с имитацией Chrome). Страница запрещает fetch на localhost (CSP),
но **обычная отправка формы** на `http://127.0.0.1:8765` проходит — на этом построен пакетный путь выше (проверено 26.09.2026).
leaderMark — из адреса страницы трейдера (`...detail?leaderMark=...`) или из скрининга `inbox/bybit_screen_2026-09-26.json`
(7089 трейдеров витрины, 1349 с признаками, описания и подключения). История у Bybit — только 90 дней.

## Стадии (factory/)

| стадия | модуль | что делает | нужно |
|---|---|---|---|
| источник | `sources/invvo.py`, `sources/bybit.py`, `sources/csvfile.py` | приводит сделки к единому формату (`schema.py`), время → UTC | — |
| 1. почерк | `fingerprint.py` | частота, монеты, лонг/шорт, удержание, **сетка свечей входа**, пачки по монетам, **фиксированные тейк/стоп**, доливки и их направление, сетка уровней, круглые цены, одновременные позиции | сделки |
| 2. тип | `classify.py` | архетип + «продаёт/покупает страховку» + бот или человек, с причинами; **сверка с самоописанием** (колонка `self_match` в реестре = точность классификатора) | почерк |
| 3. кривая | `equity.py` | доходность, просадки, по годам, **хвосты** (худший месяц в «хороших месяцах») | кривая источника или оценка по сделкам |
| 4. копия | `replicate.py` | смесь торгуемых правил (тренд/возврат/держание/**симулятор докупки**, дневные и 4ч) под дневную доходность цели; подбор на 1-й половине, **проверка на 2-й**; форма доходности | кривая ≥60 дней (<180 — «слабо») |
| 5. вход | `entry_rules.py` | подпись свечи входа, перебор библиотеки правил × режим BTC, дерево решений, проверка на последней трети | сетка свечей, ≥60 позиций, не неттинг |
| 6. выход | `exits.py` | фиксированный %, доли ATR, по времени, переворот | сделки (+свечи) |
| отчёт | `report.py` | `targets/<slug>/REPORT.md`, `passport.json`, графики; строка в `registry.csv`, запись в `JOURNAL.md` | — |

Свечи — публичный API Bybit с кэшем `data/klines/` (`market.py`).

## Как копятся знания

1. **Автоматически:** каждая цель → `targets/<slug>/` (отчёт + паспорт), строка в `registry.csv`, строка в `JOURNAL.md`.
2. **Руками после разбора (обязательно):**
   * вывод, которого не было в KNOWLEDGE.md → дописать в нужный архетип или в «Ловушки»;
   * у цели нашлось новое семейство правил входа → добавить в `entry_rules.rules()` (оно проверится у всех следующих целей);
   * завод ошибся с типом (сверка с описанием трейдера) → поправить порог в `classify.py` и записать в «Калибровку»;
   * новый источник → модуль в `sources/` + абзац в «Ловушки источников».
3. Очередь следующих целей — [QUEUE.md](QUEUE.md).
