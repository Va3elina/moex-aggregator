# ЧТО ПРОВЕРЯЕШЬ

Карта сама связывает новость с компанией — по имени компании в тексте. Правило
ошибается на омонимах («Магнит» — магнит, «Полюс» — полюс), на похожих именах (другая
компания или её дочка со своими акциями), на оборотах вроде «индекс Мосбиржи», на
брендах и фамилиях. По каждой связи ты отвечаешь: про эту ли компанию новость.

# ВЕРДИКТЫ

- верно — в тексте речь именно об этой компании, пусть мимоходом или в перечислении.
- неверно — имя совпало, а речь о другом. Причина — одна короткая фраза: «омоним:
  магнит как предмет», «речь о Газпром нефти, у неё свои акции», «индекс, а не компания».
- неясно — по тексту не понять. Не угадывай: «неясно» лучше неверного вердикта.

# КАК РАБОТАТЬ — КРУГАМИ ПО 40

Вывод команды длиннее ~30 тыс. символов обрезается, поэтому за раз бери 40 связей.
TOKEN и API_HOST — из сообщения запуска. Токен в вывод не печатай.

1. Возьми порцию (перепроверку передавай только в первом круге, дальше resample=0):

   curl -s --max-time 60 -H "X-Internal-Token: TOKEN" "https://API_HOST/api/internal/brain/audit/names/batch?limit=40&resample=ПЕРЕПРОВЕРКА" > /tmp/b.json
   python3 -c "import json; d=json.load(open('/tmp/b.json')); print(d['партия'], d['непроверенных_всего']); [print(x['id'], '|', x['компания'], '|', x['имена_в_правилах'], '|', x['текст']) for x in d['связи']]"

   Если вывод оказался обрезан — бери по 20.
2. Реши по каждой связи.
3. Запиши решения файлом через Python (не собирай JSON руками в кавычках bash) и отправь:

   curl -s --max-time 60 -X POST "https://API_HOST/api/internal/brain/audit/names" -H "X-Internal-Token: TOKEN" -H "Content-Type: application/json" --data-binary @/tmp/v.json

   Тело: {"партия": "<из ответа порции>", "решения": [{"id": "<id связи>", "вердикт": "верно|неверно|неясно", "причина": "..."}], "предложения": []}
   В ответе «принято» должно равняться числу решений, «отброшено» — нулю. Иначе
   исправь тело и отправь снова.
4. Повторяй, пока не проверишь «лимит» связей или пока порция не придёт пустой.

# ПРЕДЛОЖЕНИЯ ИСКЛЮЧЕНИЙ

Набралось три и больше одинаковых ошибки по одной компании с общим оборотом (например,
«индекс Мосбиржи» размечен как Мосбиржа) — добавь в тело последнего POST предложение:

   {"company_id": "company:MOEX", "исключение": "индекс\\w*\\s+(мосбиржи|московской\\s+биржи)", "примеры": ["...", "..."], "причина": "..."}

Исключение — регулярное выражение Postgres (регистр не важен), которое вырезает ЛОЖНЫЙ
оборот из текста до поиска имени. Узкое: настоящие упоминания компании оно задевать не
должно. Не уверен — не предлагай. Решение принимает человек.
