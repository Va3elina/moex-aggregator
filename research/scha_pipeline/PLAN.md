# Автоматический сбор справок о СЧА — план (версия 2, 15.10.2026)

Цель: каждый день находить новые справки на сайтах 7 УК, давать их прочитать агенту, заливать
прочитанное в базу и сообщать в @framesignalbot. Сначала 19 фондов акций, потом облигационные.

Почему агент, а не парсер: опыт 15.10 на 15 справках всех УК — агент по вынутому тексту прочитал
все без ошибок в рублях (одна замороженная бумага по 0 ₽ пропущена), в 4 случаях — верно там, где
парсер ошибается (Флагманский Word, TMOS 2022 разорванные суммы, TMOS 04.2023 «0 бумаг»).
Решение Вадима 15.10: проверяет агент сам себя по брифу; скриптовых проверок нет — скрипты
только «трубы» (скачать, вынуть текст, очередь, записать, сообщить).

## Схема

```
19:10 МСК  СКАНЕР (сервер)            signals/scha_pipeline.py scan
           7 сайтов УК → новая справка → архив → текст → задание scha_jobs
                     │
каждые 5 мин  ОБРАБОТЧИК (сервер)     signals/scha_pipeline.py work
           задание → в ОБЩУЮ ОЧЕРЕДЬ РУТИН (routine_queue)
                     │
каждую мин  ДИСПЕТЧЕР (сервер)        signals/routine_dispatch.py
           единственный, кто запускает рутины — для ВСЕХ заводов
                     │
           АГЕНТ-ЧТЕЦ (рутина frame-scha-reader, облако)
           GET  /api/internal/scha/jobs/{id}         текст справки + прошлый месяц фонда
           бриф research/scha_pipeline/BRIEF.md       (из репозитория, всегда свежий)
           выписывает бумаги и итоги, проверяет себя
           POST /api/internal/scha/jobs/{id}/result   таблица + «сошлось» / «сомневаюсь: …»
                     │
           ОБРАБОТЧИК: «сошлось» → в базу (interfax_manual) → ✅ в Telegram
                       «сомневаюсь» → не пишем → 🟡 в Telegram с сомнениями агента
```

| Сообщения | `research/robots_tg/robots_tg.py` → @framesignalbot | 📄 найдены · ✅ залито / 🟢 залил бы · 🟡 сомнения · 🆕 новый фонд · ⚠️ сбой |

## Задание справки: статусы

`new → text_ready → agent_wait → agent_done → imported | report_only | doubt | failed`

- `new` — файл в архиве; обработчик вынимает текст (api-контейнер) → `text_ready`
- `text_ready` → ставит рутину в общую очередь → `agent_wait`
- рутина отвечает POST'ом → `agent_done` (+ задание очереди закрыто)
- `agent_done` + «сошлось» → `imported` (или `report_only`, пока `SCHA_AUTO_IMPORT=0`)
- `agent_done` + «сомневаюсь» → `doubt` (в базу не пишем, сообщение с сомнениями)
- рутина не ответила после всех повторов очереди → `failed` + сообщение

## Защиты

| Риск | Защита |
|---|---|
| несколько рутин разом (посты + справки + …) | одна очередь, один диспетчер: ≤ 2 сессий одновременно, ≥ 10 с между запусками |
| кончилась квота подписки | ошибка запуска → пауза ВСЕЙ очереди на час, попытка не тратится, ⚠️ раз в сутки |
| рутина не ответила (5+ мин — норма) | ждём 30 мин → повтор через 5/10 мин, максимум 3 → `failed` |
| два прогона сканера / диспетчера | `flock` в .sh + advisory lock в БД |
| одна справка найдена дважды | `scha_jobs.sha256` уникален; (фонд, месяц, ссылка) пропускаются |
| повторный ответ рутины / двойная заливка | приём ответа идемпотентен; заливка только из `agent_done`, один раз |
| сбой посреди шага | статус пишется после шага, повтор продолжает с места; аренда задания 15 мин |
| подменённая ссылка на странице УК | качаем только https и только с доменов УК, редиректы тоже (SSRF) |
| сайт УК не открылся | ⚠️ раз в сутки на сайт, сканер идёт дальше |
| старые дыры в истории | сканер берёт только месяцы новее последнего залитого; новый фонд — только свежую справку |

## Режим запуска

1. **Месяц отчёта** (`SCHA_AUTO_IMPORT=0`): всё работает, вместо заливки — «🟢 залил бы: N бумаг».
   Вадим заливает как обычно, сравниваем.
2. **Автозаливка** (`SCHA_AUTO_IMPORT=1`) — после месяца без расхождений.
