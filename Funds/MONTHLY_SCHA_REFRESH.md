# Ежемесячное обновление SCHA (состав фондов /fund-trades)

> **Назначение:** раз в месяц добрать свежий месячный снапшот состава фондов
> (Справка о СЧА, форма ЦБ № 0420502) и занести в `fund_holdings_history`
> (`source='interfax_manual'`). Публикуется ~через **15-25 дней** после конца
> месяца. Парсер уже умеет PDF (Первая/ВИМ/Т-Капитал) и XBRL-Excel (Атон).

---

## Как это работает (workflow раз в месяц)

1. **Часть фондов Claude забирает сам** (сайты отдаются прямым curl — браузер не нужен):
   Первая (first-am.ru), Т-Капитал (cdn), ВИМ (wealthim.ru). Просто скажи
   «добери SCHA за <месяц>» — я скачаю, распаршу, занесу.
2. **Часть нужно скачать тебе в браузере** (e-disclosure банит сервер по IP,
   а твой локальный Chrome проходит): **Атон**, и при желании — глубокая история
   Альфа-ОПИФ. Открой ссылку → скачай «Справка о стоимости чистых активов» за
   нужный месяц → пришли мне файлы (zip/pdf/xlsx как есть).
3. Я проверяю: assets>0, Σвесов≈100%, спот-чек значений → пишу в БД.

**Именование при отправке** (если шлёшь файлы): удобно `ТИКЕР_ГГГГ-ММ-ДД`
(напр. `SBMX_2026-05-31`), но не обязательно — матчу по `isin_pif` из метаданных.

## ⚠️ Баг ×1000 в позициях ВИМ-фондов (найден и исправлен 2026-05-31)

**Симптом:** импорт **ВИМ-овского compact-PDF формата занижал `positions` в ×1000**
(а на ультра-копейках типа Россети 420 000 000 шт — в ×1 000 000) на дешёвых бумагах
(Сургут ао/ап, Мосэнерго, ЮГК, Совкомбанк, Совкомфлот, НЛМК, МКБ, ВТБ, РУСАЛ, Ростелеком,
Россети, РусГидро, Юнипро, ВУШ, ВИ.ру, Арендата). Парсер срезал последнюю разрядную
группу «000» (или две) из чисел вида «47 407 000» → хранил «47407». **`value`/`weight`/
`Σвесов`=100% — ВЕРНЫ, баг ТОЛЬКО в `positions`** → проверки по count/NAV/Σвесов его НЕ
ловят, нужен position-level diff или implied-price-скан.

**НЕ привязан к source-метке!** Затронуты ОБА ВИМ-овских stock-фонда:
**EQMX** (`source='vim_sdr'`) И **OPIF-1003 «Фонд Акций»** (`source='interfax_manual'`).
Баг в short-name-формат месяцах (имена «Сургнфгз»/«ЯНДЕКС»): 2025-01/02/03 + 2025-09→2026-04,
плюс orphan-копейки (РусГидро/Юнипро) в старых long-name месяцах вплоть до 2022-08.
**Альфа (AKME/OPIF-432), Первая (SBMX/OPIF-43/8123), Т-Кап (TMOS) — проверены, ЧИСТЫ**
(point-for-point diff + глобальный скан = 0 багов).

**Почему важно:** фронт показывает `positions` («+X шт», «было X шт», график позиций).
Диф покупок/продаж считается по `weight` → направление/проценты были верны, но «штуки» врали.

**Как пофикшено** (хирургический `UPDATE positions`, value/weight не трогал):
- даты с PDF (EQMX 02/03/04, OPIF-1003 02/03/04) — точные позиции из `parse_scha`.
- остальные — `positions * 1000^round(log₁₀₀₀(implied/ref))` где `ratio>300` против
  эталонной цены по isin (множитель сам берёт ×1000 vs ×1 000 000). `ratio>300` отделяет
  баг (~1000) от сплита 1:100 (~100); сплиты Транснефть/Норникель 2024 НЕ ложно-флагаются.
- Итого ~99 строк (EQMX ~48 + OPIF-1003 ~51). **Остаточных багов по всем фондам: 0.**

**КАНОНИЧЕСКИЙ детектор** (глобальный ref из проверенно-чистых фондов — ловит и orphan'ов,
которых фонд-специфичный ref пропускает):
```sql
WITH gref AS (  -- рыночная цена по isin из чистых фондов, недавние даты
  SELECT h.isin, AVG(h.amount_rub/NULLIF(h.positions,0)) rp
  FROM fund_holdings_history h JOIN funds f ON f.fund_id=h.fund_id
  WHERE f.ticker IN ('AKME','OPIF-432','EQMX','OPIF-1003')
    AND h.snapshot_date >= '2026-01-01' AND h.positions>0 GROUP BY h.isin)
SELECT f.ticker, t.snapshot_date, t.asset_name, t.positions
FROM fund_holdings_history t JOIN funds f ON f.fund_id=t.fund_id JOIN gref r ON r.isin=t.isin
WHERE t.positions>0 AND r.rp>0
  AND (t.amount_rub/NULLIF(t.positions,0))/r.rp > 300;   -- 0 строк = чисто
```
> Тот же `UPDATE ... SET positions = t.positions*POWER(1000,ROUND(LN(implied/rp)/LN(1000)))::bigint`
> с этим `WHERE` чинит всё разом. **При будущем импорте ВИМ-PDF — парсить `parse_scha`
> (rowwise) и сразу прогонять этот детектор перед/после заливки.**

**Остатки (не критично):** OBLG имеет vim_sdr(45 снап) с тем же багом, но OBLG —
облигации → **скрыт** в фиче (глобальный детектор bond-isin'ы не трогает, ref только stock).
OPIF-1003 держит 1 крошечную ОФЗ 26225 (`parse_scha` её пропускает, но фича облигации не
показывает). Иностранные замороженные расписки (US/NL isin) парсер ловит, импорт был RU-only.
